# F7 Discover Implementation Plan

> **For agentic workers:** Execute this plan task-by-task. Use focused parallel research agents for independent game/app verification, and a fresh review after integration.

**Goal:** Ship daily verified independent game and Android app discovery at f7developer.com/discover with real Cursor scheduling.

**Architecture:** Static dated JSON editions, pure validation/filter logic, server-only archive loading, per-edition client filters, static product detail pages, and a repository publishing command. Cursor performs bounded research and commits validated editions; Git-connected Vercel builds and publishes them.

**Tech Stack:** Existing Next.js 16, React 19, TypeScript, native CSS, Node.js 24, Phosphor icons, native Node tests, Playwright/axe.

**Spec:** `docs/superpowers/specs/2026-10-10-f7-discover-design.md`

## Global constraints

- English content; existing dark/lime F7 design; preserve supporting text readability and original studio headings.
- 7 games + 7 Android apps per day is a target; only verified entries publish.
- No Google Play API, database, paid backend, runtime scraper, or additional runtime dependencies.
- Evidence and artwork rights are mandatory, dates reflect discovery, no duplicates across history.
- Cursor schedule: daily 08:00 Asia/Jakarta; never claim scheduler success without reading saved state.

## Review focus

1. Same Android app with a renamed URL must be rejected through its package ID.
2. New-release labels must reflect original launch, not repository update dates.
3. Missing or separately excluded artwork rights must keep candidates in review.
4. A rerun must not overwrite a dated edition or silently lose review candidates.
5. Archived data must not all be imported into the client bundle; filters must survive reload/navigation.

## Decisions

- Use the already authorized website implementation/deployment scope; no extra design approval round is required before preparing the concrete result.
- Initial discoveries may be established products. Label them newly discovered unless original release evidence supports a recent launch.
- Research can run in parallel because game and app evidence/assets are separate; publishing and integration remain sequential.
